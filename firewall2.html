Arsitektur Netfilter MikroTik

Perbandingan Komprehensif 3 Filter Chains

Memahami dengan presisi batasan yuridis packet filtering untuk mencegah salah blokir atau eksploitasi remote access.

shield
CHAIN: INPUT

Melindungi Router Itself

Menangani semua lalu lintas jaringan di mana alamat IP tujuan paket (dst-address) adalah salah satu IP lokal yang terpasang pada Router MikroTik.

Target & Layanan Rentan
  • dangerous Brute Force SSH (port 22) & WinBox (port 8291)
  • dangerous Open DNS Relay Abuse (UDP/TCP port 53 via WAN)
  • dangerous BGP / OSPF / SNMP flooding & WebFig hijacking
Golden Security Rule:

Izinkan koneksi established/related, izinkan Winbox dari Subnet Manajemen terdaftar, lalu Drop ALL interface WAN di baris terbawah.

/ip firewall filter add chain=input in-interface-list=WAN action=drop
swap_horiz
CHAIN: FORWARD

Transit Traffic & Client

Menangani semua lalu lintas yang HANYA menumpang lewat router. Paket masuk melalui satu interface dan segera keluar melalui interface yang berbeda tanpa ditampung CPU lokal.

Target & Ancaman Klien
  • warning Penyebaran ransomware antar-VLAN (SMB/RDP port scan)
  • warning Serangan botnet outbound DDoS dari perangkat IoT lokal
  • warning Inbound unsolicited packet floods dari public internet
Golden Security Rule:

Terapkan FastTrack untuk paket established, blokir paket status Invalid, isolasi segmen LAN Tamu (Guest) dari LAN Server, dan drop semua paket Ingress WAN tanpa status DST-NAT.

/ip firewall filter add chain=forward connection-state=invalid action=drop
outbox
CHAIN: OUTPUT

Paket Origin RouterOS

Menangani paket yang dikonstruksi secara mandiri oleh stack kernel RouterOS. Paket ini bermula dari proses internal router dan dikirim keluar menuju jaringan lokal maupun WAN.

Operasional & Integritas
  • verified Sinkronisasi waktu presisi (SNTP Client UDP 123)
  • verified Pemeriksaan update firmware RouterOS (HTTPS mikrotik.com)
  • verified DNS Lookup forwarding recursive & Syslog telemetry
Golden Security Rule:

Secara default dibiarkan ACCEPT. Dapat difilter jika router berada pada enklaf ultra-ketat (misalnya mencegah exfiltration telemetry atau membatasi rute DNS upstream terotorisasi saja).

/ip firewall filter add chain=output action=accept
Standar Industri Defconf Hardening

RouterOS Firewall Filter Implementation

Daftar aturan urutan atas (top-to-bottom) yang wajib diimplementasikan. MikroTik memproses aturan secara sekuensial; kecocokan pertama (first match) langsung dieksekusi.

Order Chain Action Kondisi / Parameter Kunci Tujuan Fungsional Aksi
#01 FORWARD FASTTRACK connection-state=established,related Bypass CPU netfilter untuk paket terverifikasi aktif (Offload throughput).
#02 INPUT, FORWARD ACCEPT connection-state=established,related,untracked Izinkan seluruh paket balasan yang sah dari request internal sebelumnya.
#03 INPUT, FORWARD DROP connection-state=invalid Eliminasi paket anomali, corrupted flags, atau manipulasi session hijack.
#04 INPUT ACCEPT protocol=icmp limit=5,10:packet Izinkan diagnostik ping ICMP dengan rate-limiting anti Ping-of-Death / DoS.
#05 INPUT DROP in-interface-list=WAN protocol=udp port=53 Cegah router menjadi pemantul Open DNS Resolver Amplification attack.
#06 INPUT DROP in-interface-list=WAN Tolak seluruh akses langsung dari WAN menuju RouterOS (Kunci pintu router).
#07 FORWARD DROP connection-nat-state=!dstnat in-interface-list=WAN Blokir paket masuk WAN kecuali secara eksplisit di-port forward (Dst-NAT).

State Machine

Connection Tracking

Conntrack adalah jantung stateful firewall MikroTik yang merekam setiap status sesi (flow) ke dalam RAM.

NEW Paket inisiasi awal (SYN)
ESTABLISHED Koneksi telah direspons 2 arah
RELATED Koneksi anak (FTP-data, ICMP err)
INVALID Out-of-window seq / flag rusak
UNTRACKED Bypass via Raw PREROUTING
Tip: Jika CPU Router mencapai 100% akibat DDoS SYN-Flood, gunakan tabel /ip firewall raw untuk drop paket sebelum masuk conntrack.

Performance Boost

Mekanisme FastTrack

FastTrack memangkas packet processing path di Linux kernel secara radikal untuk paket yang berstatus Established & Related.

Throughput Bandwidth vs CPU Load

FastTrack melewati layer: Simple Queue, Mangle Sniffing, dan Layer 7 protocol filters untuk mendongkrak switching-rate.

Catatan: Jangan gunakan FastTrack pada antarmuka yang memerlukan Queue Tree QoS presisi.

Automated Defense

Auto-Drop Port Scanner

Jebakan honeypot dinamis: Setiap entitas eksternal yang mengetuk port terlarang secara otomatis dimasukkan ke Address List penalti.

01 Penyerang men-scan port TCP 23 (Telnet), 8080 (Proxy), atau 21 (FTP).
02 MikroTik memicu action add-src-to-address-list timeout 24 jam.
03 Aturan RAW teratas langsung men-DROP seluruh paket dari IP tersebut.
action=add-src-to-address-list address-list=BLACKLIST timeout=1d
Troubleshooting & Diagnostik

Top 5 Kesalahan Fatal Konfigurasi Firewall MikroTik

Daftar kekeliruan arsitektur yang sering menyebabkan router terkunci (locked-out) atau jaringan mengalami degradasi performa.

bug_report Security Audit Checklist
Kesalahan #01 cancel

Urutan Eksekusi Rule Terbalik

Meletakkan rule drop all from WAN SEBELUM rule accept established/related. Hal ini memutuskan seluruh sesi browsing internet dari LAN seketika.

Solusi: Urutkan Established/Related selalu di baris paling atas (Index 0/1).
Kesalahan #02 cancel

NAT Masquerade Tanpa Out-Interface

Mengatur rule chain=srcnat action=masquerade tanpa mendefinisikan out-interface=WAN. Menyebabkan paket antar-VLAN lokal ter-NAT dan IP client asli hilang.

Solusi: Wajib tentukan out-interface-list=WAN pada parameter src-nat.
Kesalahan #03 cancel

DNS Resolver Terbuka ke Publik

Mengaktifkan opsi Allow Remote Requests di IP DNS tetapi lupa mendrop port UDP/TCP 53 pada antarmuka WAN di INPUT Chain.

Solusi: Filter chain=input in-interface=WAN protocol=udp dst-port=53 action=drop.
Kesalahan #04 cancel

Lupa Mengecualikan FastTrack untuk QoS

Mengaktifkan Simple Queue untuk pembatasan bandwidth warnet/kantor namun membiarkan rule FastTrack menyala. Akibatnya bandwidth limit jebol karena paket di-bypass.

Solusi: Matikan FastTrack jika membutuhkan antrian QoS granular (Queue Tree).
Kesalahan #05 cancel

Mengunci Diri Sendiri (WinBox Lockout)

Menerapkan aturan action=drop pada chain input tanpa mengecualikan interface LAN manajemen atau tanpa mengaktifkan Safe Mode (Ctrl+X).

Solusi: Selalu aktifkan Safe Mode sebelum mengeksekusi rule firewall berisiko tinggi.
health_and_safety MikroTik Best Habit

Kaidah Operasional Safe Mode

Tombol Safe Mode di WinBox atau shortcut CLI Ctrl+X akan otomatis mengembalikan (rollback) konfigurasi jika sesi koneksi Anda terputus.
